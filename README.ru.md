## Частые вопросы

### Как задать горячие клавиши

Это делается на странице управления расширениями, например:

- chrome [chrome://extensions/shortcuts](chrome://extensions/shortcuts)
- firefox [about:addons](about:addons)

### Каков приоритет правил?

Личные правила > Правила подписки > Глобальные правила

Глобальные правила имеют наименьший приоритет, но очень важны: они служат правилами по умолчанию.

### Не проходит проверка API (Ollama и другие)

Обычные причины неудачной проверки API:

- Неверный адрес:
  - Например, у `Ollama` есть собственный API и адрес, совместимый с `Openai`. Расширение сейчас поддерживает совместимый с `Openai` адрес и не поддерживает нативный API `Ollama`.
- Некоторые ИИ-модели не поддерживают пакетный перевод:
  - В этом случае можно отключить пакетный перевод или использовать пользовательский API.
  - Подробности о пользовательском API: [Примеры для пользовательского интерфейса](custom-api_v2.ru.md)
- У некоторых ИИ-моделей параметры несовместимы между собой:
  - Например, параметры нативного API `Gemini` сильно расходятся: отдельные версии моделей не поддерживают некоторые параметры, из-за чего возникают ошибки.
  - В этом случае можно изменить тело запроса через `Hook` либо перейти на `Gemini2` (адрес, совместимый с OpenAI).
- Сервер ограничивает межсайтовые запросы и возвращает ошибку 403:
  - Например, `Ollama` требует переменной окружения `OLLAMA_ORIGINS=*` при запуске. См.: https://github.com/fishjar/kiss-translator/issues/174

### Пользовательский API не работает в пользовательском скрипте Tampermonkey

Для скриптов Tampermonkey домены нужно добавить в белый список, иначе запросы не отправляются.

### Как написать хук для пользовательского API

Пользовательские API очень гибкие и мощные: теоретически к ним можно подключить любой API перевода.

Примеры: [custom-api_v2.ru.md](custom-api_v2.ru.md)

### Как открыть страницу настроек пользовательского скрипта напрямую

Адрес страницы настроек: https://fishjar.github.io/kiss-translator/options.html

## Планы на будущее

Это проект «для души», жёстких сроков нет. Вклад сообщества приветствуется. Ниже — предварительные направления развития:

- [x] **Пакетные текстовые запросы**: оптимизация стратегии запросов, чтобы реже обращаться к API перевода и работать быстрее.
- [x] **Улучшенный перевод форматированного текста**: точный перевод сложной структуры страниц и форматированного содержимого.
- [x] **Продвинутые пользовательские и ИИ-интерфейсы**: поддержка потоковой передачи, памяти контекста, многошаговых диалогов и других возможностей ИИ.
- [x] **Запасной англоязычный словарь**: когда сервис перевода недоступен, использовать локальный словарь.
- [x] **Улучшенная поддержка субтитров YouTube**: лучше объединять и переводить потоковые субтитры, реже разрывая предложения.
- [ ] **Обновлённая система совместной работы над правилами**: более гибкий обмен правилами, управление версиями и процесс проверки сообществом.

Если какое-то из направлений вам интересно — обсудите его в [Issues](https://github.com/fishjar/kiss-translator/issues) или пришлите PR!

## Руководство по разработке

```sh
git clone https://github.com/fishjar/kiss-translator.git
cd kiss-translator
git checkout dev # PR предлагается отправлять в ветку dev
pnpm install
pnpm build
```

### Пример внешнего вызова

```js
// `toggle_translate`   включить/выключить перевод
// `toggle_styles`      сменить стиль
// `toggle_popup`       открыть/закрыть панель управления
// `toggle_transbox`    открыть/закрыть окно перевода
// `toggle_hover_node`  перевести абзац под курсором
// `input_translate`    перевести поле ввода
window.dispatchEvent(new CustomEvent("kiss_translator", {detail: { action: "toggle_translate" }}));
```
